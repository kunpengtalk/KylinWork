# 知识库模块迁移说明

## 从哪迁移的

知识库这一版的能力与交互，参照的是 **OmniStudio**（`/Users/a123/ai/OmniStudio`，仓库 `kunpengtalk/OmniStudio`）的知识库模块。

两个项目的技术栈完全不同，所以**不是拷贝文件，而是按 KylinWork 的技术栈重写**：

| | OmniStudio | KylinWork |
| --- | --- | --- |
| 前端 | React 18 + TanStack Query + Zustand + Radix | Vue 3 + Tailwind + shadcn-vue |
| 后端 | Bun + SQLite（drizzle） | Node + Express + JSON 文件存储 |
| 模型配置 | 每库一套 | 每库一套（回落全局默认） |
| 样例来源 | `apps/studio/src/{bun,mainview/app}/kb*` | `engine/knowledge.js`、`ui/src/components/knowledge/` |

## 迁移了什么

- **建库体验**：改成弹窗（名称、描述、向量 / 重排模型一次填好），替代原来「先在列表里输入名字再点新建」的内联方式。
- **每库配置**：`embedding` / `rerank` 模型、切块大小与重叠、`top_k`、相似度阈值、合并相邻分块、注入上限，都可以按库配；未配置的字段回落到「设置 → 知识库」的全局默认（老库行为不变）。换向量模型会让该库旧向量作废并提示重建。
- **数据源四类**：添加文件、导入目录、**添加笔记**（正文内联）、**添加网页**（服务端抓正文）。
- **文档级状态与分块查看**：每份资料带状态徽标与向量进度，可查看切出来的每一段（序号、标题路径、字数、是否已向量化、正文预览）。
- **召回测试**：结果标出命中来自向量 / 关键词 / 混合、是否重排，带分数条与降级说明。
- **对话引用**：答复底部列出「知识来源」（哪个库、哪份资料、第几段），事件随会话落盘，重开可回放。
- **智能体检索工具 `knowledge_search`**：智能体在跑任务过程中可以主动查知识库（检索范围默认是本次对话勾选的库）。
- **检索按库分治**：多库检索时逐库做「两路召回 → RRF 融合 → 相邻合并 → 去重 → 重排」，各库自己的模型与参数都能生效。

## 有意没有迁移

- **治理与审计**（`kb_events` 审计流水、导出 / 导入知识库）：与 KylinWork 已有的备份体系重叠，暂不做。
- **MCP 接入页**（把知识库暴露成 MCP 工具）：与 KylinWork 已有的 MCP 体系重叠，暂不做。
- **多模态直嵌**（图片 / 音频 / 视频直接算向量）：KylinWork 目前走「抽正文 → 分块 → 文本向量」，图片类只做正文抽取。

## 一处必须说明的实现差异

OmniStudio 依赖服务端自行处理超长输入。KylinWork 的向量渠道（如硅基流动的 `BAAI/bge-large-zh-v1.5`）**单条输入上限约 512 token，中文约一字一 token**——而默认切块是 800 字，超限会被服务端判 400，表现为整份文件「向量化失败」。

因此 KylinWork 在送向量前会**按模型上限截断**（默认 480 字，保留头尾、中间省略），并按总字符**分批**发送；一批失败还会对半拆开重试，个别段失败不让整份文件降级。正文、关键词索引、界面展示都是完整文本，不受影响。
